# 麦当劳 MCP 接入说明

## 使用的服务

- MCP Server：`https://mcp.mcd.cn`
- 传输方式：Streamable HTTP
- 身份认证：`Authorization: Bearer <个人 MCP Token>`
- Token 申请：<https://open.mcd.cn/mcp>
- 官方接入指南：<https://github.com/M-China/mcd-mcp-server>

每位使用者登录麦当劳 MCP 开放平台，独立申请并保管自己的 Token。Skill 不包含作者 Token，不读取本机凭证文件，也不会把 Token 写进生成的 HTML。

## 实际使用的 Tools

| Tool | 用途 | 本项目约束 |
|---|---|---|
| `order-list` | 查询当前授权用户的近期历史订单 | 只展示日期、餐品概况和份数供用户选择 |
| `query-order` | 查询用户明确选择的订单详情 | 只提取餐品、数量、定制和已选套餐子项 |

项目不调用下单、付款、取消、地址修改、领券等写操作。不同 MCP 客户端可能为 Tool 名增加命名空间前缀，Skill 以当前宿主实际声明为准。

## 调用流程

1. 检查当前会话是否存在麦当劳订单查询 Tool。
2. 调用 `order-list`，让用户选择本人一笔或多笔订单。
3. 对选中订单调用 `query-order`，展开用户已经选择的套餐子项。
4. 将原始返回转写为 `references/order-contract.md` 中的白名单结构。
5. 删除订单号、手机号、地址、支付、取餐码、门店地址和原始响应。
6. 依据已核实配方生成限量插画组件；未知餐品不使用通用图形猜测。
7. 运行零依赖构建器，生成该用户的离线 HTML 创作台。

```text
个人 Token
    ↓
order-list → 用户选择订单 → query-order
    ↓
白名单清洗 + 套餐展开 + 配方核实
    ↓
本地构建器 → 个人创作台 HTML
```

## 业务价值

历史订单通常只用于回顾消费记录。本项目把订单中的餐品转化为有真实数量限制的视觉素材，让用户通过拖拽、旋转、切割、叠加和画框导出，把消费记录变成可继续创作和分享的个人作品。

麦当劳 MCP 提供了“当前用户真实订单”这一不可替代的数据起点：不同用户获得不同餐品、数量和定制，因而生成不同的创作素材组合。Skill 负责将只读订单数据转化为创作体验，不执行交易。

## 隐私与安全

- 仓库、示例 JSON、截图和测试均只使用虚构订单。
- `mcp-config.example.json` 仅包含 `${MCD_MCP_TOKEN}` 占位符。
- 生成页不保存 Token，也不持续连接 MCP；更新订单需回到用户自己的 WorkBuddy 会话重新运行 Skill。
- 参考图默认保存在当前浏览器的 `localStorage`，不等于认证、加密或云同步。
- 麦当劳 MCP 每个 Token 每分钟最多 600 次请求；本项目仅在用户发起同步时调用订单列表和必要的订单详情。
