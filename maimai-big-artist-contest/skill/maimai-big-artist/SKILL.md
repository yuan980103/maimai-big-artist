# 麦麦大艺术家

目标体验：用户打开/调用本 Skill 后，在当前用户自己的 WorkBuddy 会话里完成订单读取、生成个人网页并立即打开，无需用户手工找 HTML 文件。每位用户必须先在自己的宿主 MCP 连接中完成授权；Skill 不能替代授权，也不能让公开网页继承会话身份。

复用 assets/studio-template.html 的创作台，按本次用户本人所选订单注入数据。使用 scripts/build.cjs 生成独立 HTML。不要修改已冻结的旧版本或原有分享网站。严格禁止将模板中的虚构示例订单用于真实创作。

## 1. 识别连接与授权

- 使用当前会话提供的工具发现能力，寻找麦当劳历史订单列表和订单详情工具。已知名称为 mcp__mcd-mcp__order-list（无参数）与 mcp__mcd-mcp__query-order（orderId 字符串）；以实际工具声明为准。
- 仅使用当前用户在宿主中授权的连接。Skill 不包含连接器，不自动安装连接器，不自行创建 OAuth 或索取密码、验证码、Cookie、访问令牌，不读取宿主凭证文件。
- 工具不可用时，明确说明“当前会话尚无可用的麦当劳订单连接”，不要生成看似已连接的空壳网页。引导用户先在自己的 MCP Client 按官方方式配置个人麦当劳 MCP Token：登录 https://open.mcd.cn/mcp 申请 Token，并在客户端配置官方地址 https://mcp.mcd.cn 与 Bearer Token。不要要求用户把 Token 粘贴到聊天、HTML、浏览器、代码仓库或 Skill 文件；不得读取宿主凭证文件。完成连接后用户再次调用本 Skill 即可生成并打开网页。不得虚构一键 OAuth、安装卡片或授权链接。
- 授权取消、查询失败、订单为空时保留现状并说明原因；可提供用户自愿上传订单截图或粘贴餐品文字的导入路径，生成时标明为手动导入，不声称已同步。
- 只读查询。不调用下单、付款、取消订单、地址修改或领券工具。

## 2. 读取本人订单（默认全量，不询问）

- 默认行为：调用订单列表后不向用户提问，直接将全部订单纳入本次创作，逐笔查询详情并合并注入；页面创作范围默认为全部订单（realScope='all'），生成后立即打开。
- 仅当用户在指令中显式指定范围时才覆盖默认值（如“只用最近一笔”“只用7月15日那笔”）。显式指定优先于默认全量；同日多单无需询问，全部纳入。
- 订单超过构建器上限（30 笔）时自动取最近 30 笔，并在页面顶部说明中注明截断。
- 对每笔订单展开实际已选择的套餐子项，不二次选套餐，不重复计数父套餐和子项。
- 仅使用本次当前账户查询得到的数据。不得复用作者、其他用户、历史会话中的订单。
- 已取消、退款等非完成状态的订单直接排除，在页面说明或回复中注明排除了几笔及原因，不询问；对详情缺失或未知定制明确列出待确认项。
- 页面顶部说明横幅应自动生成，写明本次合并订单笔数、默认范围及未核实/排除项，不手写硬编码。

## 3. 标准化与拆件

阅读 references/order-contract.md。生成最小化 JSON，仅保留日期、餐品名称、数量、定制、已核实配料与组件信息。剔除姓名、手机号、地址、订单号、支付信息、取餐码、门店地址、工具原始响应和凭证。

- 使用已确认配方或官方商品资料建立每项 recipe；历史订单名称本身不能证明完整配方。不要把整菜单包装成全部已支持。
- 使用模板已有外形，查验 foodShapes 中的键及模板绘图函数支持。未知餐品或配料先核实，或经用户同意跳过并明确说明，不能用通用块替代未知外形。
- 按订单定制处理去冰/少冰/正常冰；未注明不擅自加冰。少冰3块、正常6块及小薯20/中薯30/大薯40根是创作配额，不是门店定量。去冰0块则不生成冰块行。
- 默认冰量规则（用户确认）：可乐类固定配 3 块冰（iceCube）；橙汁不加冰；咖啡不加冰。订单定制记录优先于默认规则。
- 将甜筒拆成 cone 与 softServe；将固定汉堡酱与独立可挤酱包区分。需要当前模板未支持的酱包挤出预算时补齐逻辑并验证，不将固定酱形冒称可自由挤出。
- 默认酱料规则（用户确认）：汉堡类餐品含番茄酱时，以固定波浪 sauce 形注入（不可挤、不可自由挤出）；订单含薯条时，为每份薯条配 1 个可挤的番茄酱酱包（ketchupPacket，可挤可切割）。
- 同一套餐子项 quantity 表示每份套餐数量，构建器将其乘以父套餐 quantity。

## 4. 生成并验证

- 为每个用户或工作室新建随机、不含身份的 workspaceKey，并在之后同一工作室更新时保持稳定；共用设备切换账户时使用不同 key。只保证存储命名空间隔离，不将浏览器本地存储描述成认证或加密。
- 使用真实订单标识的不可逆摘要生成稳定的本地餐品/订单 ID，不在输出保留真实订单号。保留订单与recipe行的稳定映射，以兼容旧参考图。
- 订单导入数据使用 references/order-contract.md 的结构；不要直接嵌入原始响应或可执行脚本。
- 用可用 Node 运行 `scripts/build.cjs <orders.json绝对路径> <新的output.html绝对路径>`。优先使用宿主管理运行时。构建器零外部依赖，拒绝覆盖现有输出。输出文件名使用不含姓名/订单号的时间戳或随机后缀，写入用户可访问的工作目录；保留本次可重开的准确路径。
- 构建前清理到最小白名单数据；构建后检查页面中只含所选订单、没有真实订单号/地址/支付信息/MCP Token。用脚本语法检查并检查当前订单正确、组件配额可用。测试数据只用虚构订单，不打包真实订单。
- 成功生成后立即调用宿主的文件预览/打开能力展示该 HTML，并在回复中给出可点击文件路径。不要只告知生成成功或让用户自行寻找文件。若预览失败，说明具体原因并给出生成文件链接。
- 载入旧参考图时保持当前订单，底稿可移动旋转切割；同一订单已用素材计入限额；不自动新增订单。另存新图，保留原图。
- 当前模板仅接受当前数据集包含的素材来源。需新订单续作旧图时，保留同一用户先前订单目录和ID映射，并合并新订单，再构建新版本。不要将只含新订单的页面称为完整支持旧图续作。无法取得旧目录时明确提示并先保留旧文件。
- 生成文件后使用宿主文件预览交付。告知本次读取了几笔订单、哪些餐品尚不支持、参考图保存于当前浏览器。仅在用户明确请求公开分享时发布，发布前提示页面含个人订单餐品日期。

## 使用句式

- “打开麦麦大艺术家。”（默认读取全部订单，合并注入并直接生成、打开网页，不询问。）
- “用我最近一笔麦当劳订单打开麦麦大艺术家。”（显式指定，覆盖默认全量。）
- “把我7月15日和2月1日的订单合起来拼画。”（显式指定，覆盖默认全量。）
- “更新我的订单，让我在旧参考图上继续创作。”（重新全量读取并合并旧目录。）

## 边界

公开网址无法继承会话麦当劳授权。此 Skill 的“直接打开”指在用户自己的 WorkBuddy 会话完成读取后，自动生成并打开其个人静态创作网页；不是任何访客打开同一 URL 就能联网读取个人订单，也不是后台自动或定时同步。需要更新订单时回到该用户自己的会话再次运行本 Skill。每个用户各自配置麦当劳 MCP Token；不得在网页端采集、存储或转发 Token。
